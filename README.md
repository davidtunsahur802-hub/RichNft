# RichNft

Плагин для [exteraGram](https://exteragram.app) (Telegram-клиент с поддержкой Python-плагинов).
Добавляет **визуальные** (локальные) NFT-подарки, баланс, транзакции, бейджи и другие элементы интерфейса.

| | |
|---|---|
| ID | `richnft` |
| Версия | `1.5.1-beta` |
| Авторы | @xalveri, Чай |
| Требования | exteraGram с поддержкой плагинов (`app_version >=11.12.0`, `sdk_version >=1.4.0`). Для формата `.eaf` нужен клиент с Elyx |

## ⚠️ Прочитайте сначала

- **Почти всё работает только на вашем устройстве.** Серверы Telegram ничего не знают о «визуальных» подарках, балансе, транзакциях, бейджах и номере. Другие люди этого не увидят. Если после перезапуска клиента что-то «пропало», это нормальное поведение для локальных данных.
- **Исключение — режим «Убивашка».** Он выполняет **настоящие и необратимые действия** на вашем аккаунте: очищает историю чата у обоих собеседников, блокирует человека и отправляет чат в архив. Включайте, только если понимаете последствия.
- Плагин не создаёт настоящих платежей и не тратит реальные звёзды. Настоящие подарки он тоже не отправляет.
- Не используйте плагин для обмана других людей: поддельные скриншоты переписок, «подарков», баланса или верификации. Это нарушает правила Telegram и может привести к блокировке аккаунта.

## Что умеет

### 🎁 Визуальные NFT-подарки
- В окне подарков добавляется вкладка для **визуальной** отправки подарков (в том числе уникальных NFT).
- В чате появляется локальное сервисное сообщение о подарке; при включённых эффектах запускается конфетти.
- Подарок отображается в профиле получателя (до 6 уникальных можно закрепить сверху).
- Два режима отправки: **Новый** (для обновлённого меню Telegram) и **Старый**.
- Покупки на маркете можно скрывать, а потом вернуть кнопкой «Вернуть купленные NFT в маркет».
- Локальная отправка Premium-подарка.
- Пункты в меню чата: «Отключить визуальные подарки» и «Отключить визуальный баланс».

### ⭐ Баланс и транзакции
- **Подмена баланса звёзд** и **баланса Gram (TON)** на любое значение.
- **Списывать визуальный баланс** при визуальной покупке. Если средств не хватает, открывается штатное окно Telegram, платёж автоматически не запускается.
- **Фейк-пополнение** звёзд и Gram (запись «Fragment») в историю транзакций.
- Очистка визуальных транзакций, скрытие всех транзакций (включая настоящие, только у вас) и возврат настоящих.

### 👤 Профиль
- **Рейтинг и рамка бейджа:** уровень 1–99, форма бейджа по уровню или своя, редактор собственного контура.
- **Бейдж верификации:** `Нет` / `Hold` / `Major` / `Telegram` (с подписью в профиле).
- **Номер телефона:** отображение номера вида `+888 …` («анонимный номер»); при нажатии открывается окно Fragment.
- **NFT-юзернеймы:** добавление нескольких визуальных коллекционных юзернеймов.
- **Ношение NFT как эмодзи-статуса** (локально).

### 🔧 Прочее
- **Соо от собеседника:** всё, что вы пишете в личном чате, показывается как входящее сообщение (только у вас).
- **Убивашка:** см. предупреждение выше. Через заданное число секунд после визуального подарка чистит чат, блокирует человека и архивирует диалог. Работает только в личных чатах.
- **Цвет темы** окна настроек (пресеты или свой HEX).
- **Авто-обновление** и **диагностика** (см. ниже).

## Как это работает

Плагин перехватывает методы клиента через Xposed-подобные хуки SDK exteraGram и **подменяет данные на лету** в памяти приложения:

1. **Хуки на окна подарков и покупки** добавляют вкладку и перехватывают «покупку», чтобы вместо запроса на сервер создать локальный подарок.
2. **Хуки на `ConnectionsManager.sendRequest`** отвечают локально на часть запросов (статус эмодзи, информация о коллекционном юзернейме) и подмешивают визуальные подарки в ответы со списком подарков профиля.
3. **Хуки на контроллеры звёзд** возвращают заданный баланс.
4. **Хуки на профиль** (`ProfileActivity`, `StarRatingView`) меняют рейтинг, бейдж и номер и рисуют свой бейдж уровня поверх штатного.
5. Локальные данные (подарки, транзакции, настройки) хранятся в настройках плагина на устройстве.

Хуки для номера и баланса ставятся, **только когда соответствующая функция включена**, и снимаются при выключении. Это снижает нагрузку.

### Настройки
Открываются со страницы плагина. Три вкладки: **Профиль** (рейтинг, бейдж, номер, юзернеймы), **Баланс** (звёзды, Gram, фейк-пополнение) и **Прочее** (эффекты, режим отправки, «Убивашка», маркет, тема, обновления, диагностика).

## Установка

**Вариант 1: `.plugin` (один файл)**
Отправьте файл `Rich1_5_beta.plugin` себе в «Избранное» и нажмите на него в exteraGram → «Установить».

**Вариант 2: `.eaf` (Elyx-архив)**
Это ZIP с `refmap.yml`, `metainfo.yml` и `main.py` в корне. Устанавливается так же. Нужен клиент с поддержкой Elyx. Внутри тот же код.

## Авто-обновление

Плагин сам проверяет наличие новой версии (при загрузке и при открытии чата, не чаще раза в 6 часов; фоновых таймеров нет) и показывает окно **«Обновить / Позже / Пропустить»**.

**Настройка для автора:**

1. Создайте репозиторий на GitHub и положите в него `version.json`:
   ```json
   {
     "version": "1.5.2-beta",
     "url": "https://github.com/ВАШ_НИК/ВАШ_РЕПО/releases/latest/download/Rich1_5_beta.eaf",
     "changelog": "Что нового в этой версии",
     "sha256": "хэш файла (необязательно)"
   }
   ```
2. В начале файла плагина укажите ссылку на raw-версию этого файла:
   ```python
   UPDATE_MANIFEST_URL = "https://raw.githubusercontent.com/ВАШ_НИК/ВАШ_РЕПО/main/version.json"
   ```
3. Для каждого релиза: загрузите файл в **Releases** под тем же именем и поднимите `version` в `version.json`.

Если указан `sha256`, плагин проверит файл перед установкой. Пока в `UPDATE_MANIFEST_URL` стоит `OWNER/REPO`, проверка отключена.

> Скачанный файл открывается через системное окно установки exteraGram, поэтому подтвердить установку нужно одним нажатием. Если клиент не откроет файл сам, плагин откроет ссылку на него в браузере.

## Диагностика и производительность

В **Прочее → Диагностика**:
- **Подробные логи** выключены по умолчанию (чтобы не тратить батарею). Включайте только при поиске проблем.
- **Отправить логи** отправляет буфер логов. При включённых подробных логах в конце добавляется таблица **нагрузки хуков**: сколько раз вызывался каждый хук и сколько времени занял.
- **Очистить** сбрасывает буфер.

### Что оптимизировано в 1.5.1
- Кэш настроек, `_my_id` и проверки «нужна ли подмена»: хуки больше не читают хранилище на каждый вызов.
- Хук `getUser` (вызывается тысячи раз в секунду) работает по быстрому пути.
- Устранён бесконечный цикл обновления профиля (`userInfoDidLoad`) и обход дерева View на каждый кадр скролла.
- Бейдж уровня на профиле рисуется из кэша Paint/Path, а не пересоздаётся каждый кадр.
- Лишние `invalidate()` в `onMeasure` и `requestLayout` убраны.
- Логи не пишутся без включённых «Подробных логов».
- Ленивая установка хуков номера и баланса, ограничение размера внутренних словарей.

## Известные ограничения

- Версия **beta**: возможны ошибки, особенно после обновлений Telegram или exteraGram (плагин опирается на внутренние классы клиента).
- Тихая замена плагина без окна установки в SDK не задокументирована, поэтому обновление требует одного подтверждения.
- Профайлер хуков может не работать на клиентах, где хуки вызываются не через экземпляр класса; в этом случае таблица будет пустой.
